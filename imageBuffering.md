## Key Methods for Image Rendering
- Dedicated Image-Push Functions: Most display libraries, such as TFT_eSPI and Adafruit GFX, include functions to push entire images or bitmaps from memory (Flash, SD card, or RAM) to the screen in a single, optimized operation.
    - pushImage() / drawBitmap(): These library functions handle the bulk data transfer to the display controller via the SPI or parallel interface. The raw image data (often in 16-bit RGB565 format) is sent top-down or in another optimized sequence, which is much faster than managing individual pixels with drawPixel() in a loop.
- Sprites/Double Buffering: You can draw all your elements (images, text, shapes) to an off-screen memory buffer (a "sprite" in TFT_eSPI terminology) and then rapidly copy the entire buffer to the visible screen once the frame is complete. This prevents flickering and provides a smooth display, which is ideal for animations or frequent updates.
- Direct Memory Access (DMA): High-performance microcontrollers (like ESP32 or STM32) can use DMA to offload the memory-to-display transfer from the main CPU, allowing the processor to prepare the next frame while the current one is being sent to the screen.
- Hardware Acceleration (DMA2D): Some advanced MCUs include dedicated hardware for 2D graphic operations (like DMA2D in some STM32 chips) which can accelerate the process of copying and blending image data.
